# 歌手与专辑详情

歌曲中的歌手和专辑名称有可靠 QQ MID 时提供链接。多位歌手显示选择弹层，不凭合并姓名猜测身份；缺少 MID 但有歌曲 MID 的旧记录，名称仍可点击：仅在点击时查询真实歌曲身份，随后打开对应详情；不会在启动时联网补齐。入口覆盖搜索结果、推荐/详情曲目表、喜欢、下载、底部播放器和正在播放详情。

## 页面

- 歌手：圆形头像、姓名、可展开的真实简介、最多 50 首热门歌曲、每页 20 张专辑。默认预览前 20 首热门歌曲及前 10 张专辑，底部「查看更多」展开当前列表；展开专辑后继续分页。预览/展开状态随浏览历史恢复。歌曲表省略重复歌手列，桌面展示可点击专辑列，窄窗口在歌名下展示专辑。顶部不提供「查看专辑」快捷按钮。支持播放/下载热门、单曲收藏/下一首/下载、专辑跳转和专辑分页；热门歌曲不是该歌手全部作品。
- 专辑：封面、名称、歌手、发行日期和按服务原始顺序排列的完整曲目。每页展示 50 首，播放全部和下载全部使用完整集合，不以当前可见页作为全集。保留多碟/合集中的重复曲目出现次数，下载继续按已有安全去重规则处理。
- 共享当前深色样式、SongTable、收藏、下载、封面和播放器组件，错误、加载、空列表分开呈现，不使用模拟数据。没有日期/简介等字段时不补造。
- 顶部后退、前进及页面返回保留具体歌手/专辑、专辑页码、曲目页码和滚动。刷新当前详情绕过缓存，但不改动音频、队列、进度、收藏或任务，也不重启播放器。异步代次和导航所有者阻止迟到回复抢回页面。

## 固定 QQ 匿名元数据接口

共用 `https://u.y.qq.com/cgi-bin/musicu.fcg` 的有界、无 Cookie、无跳转客户端，和音源脚本/密钥无关：

- 歌手：`music.web_singer_info_svr.get_singer_detail_info`，参数 `singermid`、`sort=5`、`sin=0`、`num=50`。
- 歌手专辑：`music.musichallAlbum.AlbumListServer.GetAlbumList`，MID、20 条偏移及 `order=0`。
- 专辑信息：`music.musichallAlbum.AlbumInfoServer.GetAlbumDetail`。
- 专辑完整曲目：`music.musichallAlbum.AlbumSongList.GetAlbumSongList`，`order=2`，每次最多 100 首，同一专辑最多 1000 首。校验响应 MID、总数、当前偏移和每页准确数量；任何失败都不返回部分专辑供“全部”操作。

MID 只允许 1–64 位 ASCII 字母数字。请求单次最多 8 秒、2MiB，整个详情有独立 35 秒预算与取消通道，不取消搜索、推荐、歌词、音源解析或下载。歌手专辑最多 100 页；不自动翻完全部作品。前端最多缓存 8 个详情/分页，五分钟内返回复用，均仅驻留内存。固定 QQ CDN 根据安全 MID 构造封面，不使用服务中的跳转、广告或媒体地址。

接口为非承诺开放的匿名元数据服务，可能被平台限制或改变。不登录、不绕过限制、不自动重试/换源；用户可显式重试。歌词、媒体解析仍走原有独立链路。

## Wails 和持久化

`GetMusicDetail(kind, mid, albumPage, requestID)` / `CancelMusicDetail(requestID)`，客户端不能传网络地址。

SQLite schema 4 的 Song JSON 兼容增加 `artists` 和 `albumMid`。新加入的收藏、暂停播放队列和下载记录保留身份信息；旧记录仍兼容，不按名称猜 MID、不后台联网补齐。缺少身份标识的旧记录在显式点击时通过 `GetSongCredits(songMid)` 查询 `music.pf_song_detail_svr.get_song_detail_yqq`，只接受与请求相同的歌曲 MID。查询单飞并有界缓存；在途结果不会把已离开的页面拉回。当前队列中匹配歌曲补齐后，前端持久化同时写入 `artists` / `albumMid`，不改变歌曲选择、进度、队列顺序或音频状态。

`qq-metadata.jsonl` 只增加固定操作 `artist_detail` / `artist_albums` / `album_detail` / `song_credits` 和原有数字状态/耗时，不写姓名、简介、MID、专辑名、歌曲名、URL、脚本、密钥或响应正文。
