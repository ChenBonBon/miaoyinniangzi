# 音源隔离校验、启用与解析

## 已实现与边界

- 每次导入成功后（包括重复导入）自动在隔离进程中离线校验，不自动启用；保留手动「校验 / 重新校验」入口。
- 导入与校验由 Go 后端连续编排，切换页面不会取消流程。校验失败保留加密副本；若校验中断或结果无法保存，单独报告「已保存，但校验未完成」，不误报导入失败。
- 校验时，在独立进程中运行 Goja，验证脚本完成 `lx.EVENT_NAMES.inited` 初始化、注册了 request 函数、声明 `tx` 的 `musicUrl` 动作，以及普通音质能力。
- 只保留 `flac`、`320k`、`128k`，按优先级返回，不接入其他音乐平台或特殊音质。
- 提供 `lx.on`、`lx.send`、事件名称、env/version、静默 console、受限 setTimeout/clearTimeout。`lx.utils` 暂为空，不支持 Node.js 模块、fetch、定时循环或完整洛雪工具集。
- 检查阶段的 `lx.request` 仅回调本地错误，不读取 URL/headers、不联网、不自动更新脚本。需要联网或额外 API 才能初始化的脚本可能无法通过，不能把这种失败解释为音源服务失效。
- 离线校验只验证初始化与能力声明，不证明服务可达。真实解析是独立的显式操作，见下文；真实播放见 [播放链路](playback.md)，歌词和下载尚未接通。

## 进程和安全

主应用从 SQLite 读取密文，用 Keychain（macOS）或 DPAPI（Windows）保护的密钥解密，脚本只通过匿名 stdin 管道发送给 `--miaoyin-source-worker` 分支。macOS 使用同一二进制；Windows 使用相邻的最小 Go 辅助 EXE，不加载 Wails、SQLite、凭据存储或播放器。该分支位于 Wails、数据库及 Keychain 初始化之前。密钥不传给辅助进程，脚本不写入参数、环境变量或临时文件。

macOS 辅助进程在加载脚本前：

1. 应用 macOS Seatbelt 默认拒绝策略（只开放 sysctl-read）。
2. 禁止 core dump 和文件写入，限制 CPU 时间、文件描述符数量。
3. 使用无 HOME/凭据的最小环境、根目录作为工作目录，设置 64MiB 的 Go 软内存预算。
4. Goja 栈限制为 128，禁用 source map 自动加载；仅允许最多 32 个初始化定时器。

主应用设置 3 秒整体超时，Goja 1 秒执行中断，监控辅助进程 RSS（192MiB 阈值，每 10ms 采样），超限或连续无法监控时终止进程。内存采样和 Go 软预算不是精确硬上限，瞬时峰值可能超出阈值。

stdout 只接受不超过 8KB 的固定 JSON 报告，校验所有结果字段；stderr 丢弃。脚本 console、异常正文和堆栈都不进入主应用日志或前端。返回的错误只使用固定的脱敏消息。

**平台限制：** Apple 已弃用 `sandbox_init`，当前 macOS/Xcode 环境测试可用，并会产生编译警告。限制设置失败时拒绝检查，绝不在主进程或无沙箱模式下回退。正式发行前应迁移/评估签名后的 XPC + App Sandbox 辅助服务，并在目标 macOS 版本验收；当前不是对未来系统兼容性或绝对防逃逸的保证。

## Windows 路径

Windows 使用创建时 AppContainer/LPAC（零网络 capabilities）+ Job list、暂停启动后核验实际 image/令牌/Job 再恢复、三个标准句柄白名单、最小环境及只读程序 staging；worker 在读脚本前再次自检。内存以 Job 提交内存硬限制（256MiB）和父进程 RSS 监控（192MiB）共同约束，单进程、2 秒用户 CPU、禁止子进程、完整 UI 限制及 kill-on-job-close。无安全降级或普通进程回退。独立的 Windows EngineVersion 要求旧检查状态重检，不自动启用。

实现已接入，但 Windows 原生测试仍待用户运行，不把交叉编译当作安全验收。完整边界、目录 ACL、原生越权/父退出探针、实际辅助 EXE 冒烟及剩余限制见 [Windows 沙箱](windows-sandbox.md)。

## 真实解析

搜索结果中的「解析」按钮通过 `ResolveSong(song, requestID)` 发起解析，使用当前启用音源及已保存的播放音质偏好，与下载音质独立；`CancelSongResolution(requestID)` 只取消当前匹配的解析，不影响歌曲搜索与输入提示。当前为解析验收入口，不播放或下载。

主进程在管理锁内读取当前音源快照、从 Keychain 取得密钥并解密，随后释放锁再联网。脚本经匿名管道发送给同一二进制的 `--miaoyin-source-resolver` 分支，macOS 分支同样在 Wails、数据库、Keychain 初始化前进入 Seatbelt 沙箱；Windows 的最小辅助程序在创建时进入 LPAC/Job，并在读脚本前再次核验隔离配置。每个音质尝试使用短生命周期进程，明文缓冲尽力清理，不写入文件；Go/JS 内存副本不保证可逐一擦除。

- 只调用 `musicUrl`、`source=tx`；白名单投影歌曲 MID、数字 ID、media MID、歌曲/歌手/专辑名，不传入封面 URL、任意前端地址或数据库内容。
- 支持 `lx.on/send/request`、Promise、有限定时器与静默 console；`lx.utils` 仍不是完整工具集。网络 callback 返回 `statusCode/body/headers`，JSON 正文自动解码；支持 GET/POST、字符串/JSON body、受限字符串 headers。
- 初始化期间的请求始终本地失败，忽略更新提示并取消遗留初始化定时器，不联网检查或安装更新。
- 按已保存偏好和声明能力，依次尝试 FLAC → 320k → 128k，只向下选择，不自动切换音源。处理器拒绝或未返回字符串地址可尝试下一档；网络/安全错误、HTTP 401/403/429 及常见 JSON `code` 401/403/429 停止，不继续降级请求。
- 成功返回源 ID、歌曲 ID、请求/返回档位、降级标记和地址。前端只保留状态和档位，不展示、持久化或记录签名 URL；取消及迟到响应不会显示成功。
- 档位表示向音源请求的普通音质，不等于已检测音频编码；解析不读取媒体正文，不证明链接可播、未过期或具备播放授权。
- 禁用、切换、删除当前音源或重检当前项会取消正在进行的解析；返回前再次确认当前项仍启用且版本序号未变，不发布旧选择的结果。不会因解析失败自动禁用或补选音源。

### 受控网络与资源

worker 没有直接网络权限，stdout/stdin 使用严格、有界 JSONL 双向协议，主进程校验后代发请求。音源接口请求仅允许 HTTPS、公网目标、默认 443 端口；禁止 URL 用户名密码、fragment、本机/内网/链路本地/云元数据及特殊 IP 段，包括本机网卡绑定的公网地址。每次连接重新解析 DNS，拒绝混合公私网答案，并直接拨号已验证 IP，保留原主机 TLS 校验，防止 DNS 重绑定。

若系统 DNS 全部返回 TUN/Fake-IP 的 `198.18.0.0/15` 合成地址，不会直接拨号这些地址，而是向固定 AliDNS HTTPS DNS 服务（证书主机 `dns.alidns.com`、启动 IP `223.5.5.5`）查询真实 IPv4 地址，再执行相同的公网/本机网卡校验并固定 IP 拨号。这里只发送目标主机名，不发送 URL 路径、query、headers 或正文；响应限 16KiB、请求限 3 秒。私网答案、混合答案和直接提供的 benchmark IP URL 仍拒绝；该兼容路径失败时不绕过校验。

不使用环境代理、Cookie jar、系统登录凭据；仅转发脚本显式提供的受限 headers，拒绝 Host、Cookie、代理凭据和连接控制头。不跟随重定向，不能把带鉴权的请求自动转发到另一站点。HTTP、非默认端口、需要重定向或额外 LX API 的源可能不兼容，当前不会降低安全限制来兼容。

- 解析任务上下文预算 25 秒（无法强制打断系统钥匙串授权等待；授权返回后若已过期则取消）；每个音质进程 12 秒、VM 墙钟中断 10 秒，仍受 CPU 2 秒、192MiB RSS 监控及 64MiB 软内存预算限制。
- 每个音质最多 6 次网络 RPC，单请求 6 秒；请求正文 ≤64KiB、headers ≤32 项/16KiB，响应解压后 ≤1MiB、响应头 ≤32KiB。
- 初始输入帧 ≤2MiB，worker 输出帧 ≤192KiB；拒绝未知字段、额外结果、尾随输出、任意异常文本和不匹配音质。
- 返回媒体地址与鉴权接口分开验证，允许公网 HTTP/80 或 HTTPS/443；其他协议、异常端口、用户名密码、fragment、内网地址、混合 DNS 答案及本机网卡地址仍拒绝。HTTP 媒体地址只被验证和返回，不在解析阶段读取正文，不放宽音源接口的 HTTPS 限制。播放已通过独立的受控媒体读取路径处理重定向、DNS、Range、流量和容器探测，不能把解析校验视为浏览器直接请求的安全保证，见 [播放链路](playback.md)。
- 脚本、请求地址/headers/body、响应正文、原始异常和媒体 URL 不写日志；解析不使用 QQ 元数据诊断日志。

## 状态与选择

SQLite schema v3 为音源保存检查状态、脱敏错误、运行器版本、普通音质和 active 状态。

- 新保存副本：`unchecked`，紧接着自动校验，单选按钮禁用。
- 校验通过：`ready`，允许单选，但不自动选中。
- 校验失败：`failed`，保留副本并显示错误；若是当前启用项，同时清除其 active 状态，不自动切换其他音源。
- 启用前重新解密并重新检查，不能仅凭缓存徽标启用。
- 切换采用事务，数据库唯一部分索引保证最多一条 active。新音源启用失败时保留原选择（若原音源自身检查失败则禁用）。
- 当前项提供「禁用」，允许零个音源启用；删除当前项同样回到零个，不自动补选。
- 重启恢复选择和检查信息。运行器版本变化后清除过期检查及选择，要求重新检查。
- 启用表示保存一个已通过本地检查的选择，不是常驻后台进程，也不会自动开始播放。

当前选择仅在音源列表中显示，顶部统一为搜索栏，不显示音源名称。音质下拉列表按已启用音源的普通能力过滤；原先保存但当前不支持的偏好保留为禁用选项，不静默改写设置。

## 验证

```sh
go test -race ./...
go vet ./...
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
cd frontend
npm run check
npm test
npm run test:e2e
```

测试包括：

- 新导入与重复导入均自动校验，不自动启用；校验失败或中断保留副本，支持后续手动校验。
- 有效/缺失 tx 声明、初始化失败、Promise 与受限定时器初始化。
- 死循环中断、取消、内存密集脚本终止、独立进程协议。
- 在真实受限子进程中验证原生文件读取、网络连接和子进程启动被系统拒绝。
- 密钥丢失、失败检查不泄露脚本异常、启用前重检。
- 单选约束、切换失败回滚、禁用、删除不补选、重启恢复及缓存过期。
- 前端检查/切换/失败状态；后端成功前不显示选中；音质过滤不改写偏好。
- 隔离进程的真实协议往返、QQ 字段映射、Promise/定时器、初始化请求阻断、异常脱敏、取消、非法帧和网络请求预算。
- 公私网 IP、混合 DNS、IP 拨号固定、防重绑定、鉴权头规则、重定向、响应上限及已知授权/限流停止。
- 当前源快照解密、音质降级、不升级偏好、禁用取消、不保留明文缓冲；前端成功/降级/失败/取消，不请求媒体或自动播放。

真实缓存、下载、原生播放/跳转的重型集成测试需额外使用 `go test -tags source_live`，并继续显式设置原有 opt-in 环境变量；默认测试二进制不静态链接这些测试的 SQLite、C 运行库、播放器依赖，避免其在 Windows lowbox 的 `TestMain` 之前初始化。该编译标签只选择测试，不放宽任何 OS 隔离策略；Windows 默认原生探针不应带此标签。

可通过环境变量 `MIAOYIN_SOURCE_TEST_PATH` 显式提供真实脚本进行离线冒烟检查，测试输出仅包含普通音质列表，不输出正文或密钥。默认自动测试不访问真实用户音源、数据库或 Keychain。新增 `TestProvidedSourceResolveOffline` 同样需显式设置该变量，用伪造网络响应验证真实脚本的 FLAC handler，但不会联系音源服务或消耗服务额度；不能用它证明线上解析可用。

可用 `MIAOYIN_LIVE_SOURCE_PROXY=1 go test -v ./internal/sourcenetwork -run TestLivePublicHTTPSProxy` 验证实际的公网 HTTPS/IP 固定拨号路径，目标是匿名 QQ 元数据接口，不使用音源服务或密钥；本次在实际 Fake-IP 网络中通过，完整客户端交互仍需验收。

另有 `TestProvidedSourceResolveLive`，必须同时显式设置 `MIAOYIN_LIVE_SOURCE_RESOLVE=1` 和 `MIAOYIN_SOURCE_TEST_PATH` 才联系真实音源，单次只尝试 FLAC，不播放或下载；可能消耗服务额度。修复 HTTP 媒体地址误拦截后，提供的脚本已完成一次线上 FLAC 档位解析，测试只输出状态、协议分类和档位，不输出 URL、headers、正文或密钥。

运行时超时、资源限制、进程退出、协议异常、媒体安全拒绝及媒体 DNS 校验失败使用独立的固定错误分类，管理层只允许这些脱敏消息透传，不再一律误报为资源限制。

当前使用 Go 1.27.3、Wails v2.17.0 和更新后的 Goja/传递依赖验证；旧 Go 1.25.3/Wails v2.11.0 兼容绕过已移除。升级后的 `govulncheck` 扫描无已知漏洞。
