# 外观

设置分类新增「外观」，主题可选「深色」「浅色」「跟随系统」。默认深色，保留原有界面；切换即时预览，没有保存按钮或常驻成功提示。

- 深色保持原有中性色和强调色；浅色使用同一强调色及独立的背景、侧栏、文字、边框、焦点和错误色变量。播放器、队列、弹窗、表单及 toast 共用语义颜色。系统原生表单和滚动条同步 `color-scheme`。
- 跟随系统保存的是 `system` 而非当时解析出的深/浅色。应用运行中监听系统偏好变化，只有跟随系统时改变实际配色；手动深/浅色不受系统变化影响。
- macOS 通过主队列设置当前 `NSApp.appearance`，跟随系统时清除 override；不修改系统外观或其他应用。Windows 通过 Wails 的原生窗口主题接口同步。浏览器模拟系统变化不能代替原生窗口标题栏验收。

## 保存与启动

SQLite schema 4 的 `state.appearance_v1` 单独保存字符串枚举，不迁移 schema，不修改已有音量/播放/下载设置。专用 `GetAppearance` / `SaveAppearance` 有界访问本地存储；启动仅单独读取外观，不提前加载设置页或运行音源。旧版没有此记录时默认为深色；未知/损坏记录报读取失败，不自动用默认值覆盖。

前端即时预览、串行写入并合并最新选择。保存失败保留当前预览，设置中显示失败及「重试保存外观」；读失败保留启动外观，禁用选择并提供「重试读取外观」，不自动写入默认值。切页不丢失保存任务。其他设置的旧草稿不能覆盖主题，主题变化也不提交音量/目录/音质草稿。

WebView localStorage 的 `miaoyin-appearance-v1` 只镜像已确认的枚举，供 HTML 在首屏绘制前应用配色。SQLite 是权威；缓存缺失/损坏或浏览器拒绝访问不会阻止启动，后续读取 SQLite 校正。该键不包含路径、脚本、密钥或音乐标识。没有另一套 mode-watcher 持久化状态与之竞争，Sonner 使用应用解析后的外观。

## 验证与验收范围

自动检查覆盖 SQLite 默认值/重开/独立保存/无效和损坏数据，桥接不可用/非法输入，系统偏好解析，串行最新选择（含在途写入时改回原值），读写失败/显式重试/不覆盖默认值。浏览器验证三种模式、运行中系统变化、手动选择不受系统影响、重载恢复、独立保存、读写失败、浅色说明文字对比度 ≥4.5:1 及紧凑布局；检查深/浅色截图。自动化不切换整台机器的系统外观、不播放或下载用户音乐。

本轮已通过 Go 全项目 race/vet、Windows 全项目交叉编译/vet、前端类型检查（零错误/警告）、128 条单测及 Chromium/WebKit 各 101 条 E2E。`python3 tools/test_appearance_macos.py` 另在无个人配置的独立进程验证实际 AppKit 主队列实现的深色、浅色及清除 override，三项均通过；未改变系统偏好。浏览器对比度与截图检查通过，不代表用户完整应用已经验收。

用户已在 `macos-appearance-2c0abca` 完整包反馈 macOS 外观功能测试通过，另要求首次进入设置默认定位「外观」而非「播放」；该默认锚点已调整，前进/后退仍恢复浏览位置。调整后的锚点待复验，Windows 新外观功能仍待分别验收，不由之前的基础功能验收推断通过：

1. 设置 → 外观，切换深色和浅色，确认正文、侧栏、播放器、表单、队列、弹窗、toast 与原生标题栏一致，文字清楚、焦点可见。
2. 选择跟随系统，再由用户切换系统外观，确认应用响应；切回手动深色/浅色后，系统变化不应改变手动选择。
3. ⌘Q / 正常退出后重开，主题选择保留，不自动播放或下载。
4. 切换主题后检查原有音量、音质、下载目录、收藏和队列未被改写。

只记录当前设备与系统的结果；macOS 13、其他 Windows 环境和辅助技术行为不因本轮测试自动视为通过。
