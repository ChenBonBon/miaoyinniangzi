# 喜欢的音乐

左侧主导航提供独立「喜欢」入口，打开「喜欢的音乐」页面；推荐页不再放置收藏标签。列表按需加载，搜索结果、底栏和播放详情共享同一个收藏状态。搜索行的收藏按钮位于「下一首播放」之后；底栏和播放详情的收藏按钮紧跟歌名。未收藏为空心，已收藏统一为红色实心爱心。

## 行为

- 爱心切换收藏/取消收藏；成功持久化后才改变图标，不乐观冒充保存成功。
- 同一歌曲保存期间，各入口同步禁用；不同歌曲的写入按点击顺序串行提交。新增项置顶，重复加入不改变原顺序，取消后重新收藏成为最新项。
- SQLite 沿用已有 favorites 表和 schema 4，不增加登录、云同步或自建歌单。记录歌曲标识、基础元数据及小数秒时长，不保存解析 URL、源脚本或密钥。
- 列表支持点选播放、播放全部、下一首播放和取消收藏。播放时复制当前收藏列表作为独立播放队列；取消收藏只改变收藏列表，不停止音频，不删队列项，不触碰本地文件。
- 列表每页 50 项，减少大收藏列表的 DOM 数量。超过现有 10000 首队列上限时明确显示「播放本页」，点选也仅以本页建立队列，不静默截断整个收藏。
- 启动仅读取本地收藏，不解析歌曲或创建播放器。重启保留收藏，仍按原规则恢复暂停播放状态。
- 收藏列表已提供单曲和「下载全部」，复用 [下载任务](downloads.md) 的设置快照、安全去重和断点验证。

## 失败处理

读取失败显示独立错误与重试，不把错误当作空收藏，不清空此前已确认的数据；未知收藏状态时不允许盲目写入。保存失败保留原图标并提示重试，不展示成功 toast。刷新在写入期间禁用，防止旧读取覆盖新提交。

`favorites-controller.ts` 负责单次进行中的读取、有序写入、待保存 ID 和确认快照，`favorites-state.svelte.ts` 提供跨组件共享状态。收藏改变不依赖播放器事件，也不调用媒体控制或队列变更方法。外部进程修改收藏可手动刷新，不承诺跨进程实时同步。

Go 边界验证 QQ 标识和歌曲参数、拒绝无存储状态；数据库错误统一为固定中文消息，不把路径或内部错误传给界面。SQL 使用参数绑定，文本由 Svelte 转义。

## 验证

- 单元测试覆盖读取合并、缺失元数据规范化、确认后提交、重复点击、不同歌曲有序写入、失败保留、错误恢复及损坏快照拒绝。
- Go 测试覆盖新增倒序、重复加入不重排、重新收藏置顶、小数时长、数据库重开、非法标识拒绝、播放快照和真实临时文件不被改动。
- Chromium/WebKit 覆盖搜索/底栏/详情同步、无意外播放、重启恢复、整列表播放、删除当前收藏不打断队列、保存中禁用、读写失败和重试、分页与窄窗口。真实客户端交互与播放听感仍需验收。
