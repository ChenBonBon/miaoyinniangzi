# 推荐：榜单与新歌

推荐页直接展示 QQ 榜单分组，不再显示榜单／新歌切换；新歌通过 QQ 的新歌榜浏览。不直接铺满曲目，不使用账号个性化推荐。入口和列表都是 QQ 真实匿名元数据，和音源脚本及密钥独立。

## 界面

- 榜单按 QQ 返回的分组、顺序、标题、封面及更新日期展示，点击进入曲目页。地区新歌适配器保留，但推荐界面不再展示其独立入口。
- 曲目页展示标题、封面、日期/榜期和曲目数量；每页显示 50 首。支持点选播放、播放全部、收藏、下一首播放、单曲下载和下载全部。
- 播放全部与下载全部使用已取得的完整列表，不以当前显示页作为全集。浏览入口/翻页只请求元数据，不解析音乐、不自动播放或下载。
- 返回推荐恢复目录滚动与入口焦点。播放详情返回保留原曲目页及页码；页面卸载取消未完成推荐请求，成功快照在内存保留，不中断音频。
- 首次无缓存时，失败通过 toast 提示「暂时无法读取推荐」，不在正文显示错误卡片、不冒充空目录/空列表；已有成功内容时，刷新期间保持可浏览/播放，失败通过 toast 提示「更新未完成，已保留上次内容」，不挤占列表空间。toast 附错误原因、不含重试按钮；仅新失败触发一次，用固定 ID 合并提示，重试或恢复时清除旧提示。用户通过顶部「刷新」显式重试，取消或迟到回执不弹错误。推荐页不再提供配置音源按钮，音源管理仍在设置中。
- 曲目表格复用现有封面、收藏、下载和播放器控制组件，遵循当前深色主题、键盘及 reduced-motion；封面懒加载，失败使用唱片图标。

## 自定义推荐布局

目录右上角的「调整」按需加载侧边面板，支持独立显示/隐藏分组和组内榜单、分组排序、同组榜单排序。面板沿用音乐列表的封面/名称样式，眼睛图标独立控制显隐，隐藏项淡化；分组手柄、上下排序箭头仅在悬停或键盘聚焦时出现，触屏保持可见。榜单可直接拖动小封面，或聚焦后使用上移/下移按钮；不允许跨组拖动榜单。隐藏分组不改变组内选择和顺序，面板仍可调整隐藏组的内容。全部隐藏时提供独立空态，调整入口仍可使用。

调整即刻预览并串行自动保存，快速连续修改只会让最新布局最终落盘。读失败不自动写入默认值；写失败保留草稿并明确提示尚未保存，支持重试。正常保存后不常驻显示成功状态，仅在保存中或失败时显示状态。关闭面板或切换页面不取消在途保存。「恢复默认」需确认，清除全部自定义排序和隐藏标记。面板具备焦点约束、Esc 关闭、关闭后回到调整按钮、排序结果读屏提示及 reduced-motion 支持。

偏好通过 `GetDiscoveryPreferences` / `SaveDiscoveryPreferences` 保存到现有 schema 4 SQLite `state.discovery_preferences` 键，无需迁移，不放在音源设置或播放队列中。分组以 QQ `groupId` 标识（包括 0）；没有 ID 时以分组名兜底，榜单以数字 topId 标识。存储只包含标识、顺序和隐藏标记，不存封面地址、音乐地址、脚本或密钥。Go/前端校验重复标识、类型、范围和最多 32 组、合计 1024 条偏好，失败不覆盖旧记录。

QQ 新增分组默认追加到分组末尾，组内新增榜单默认追加在组内末尾并显示；已自定义项目不按 QQ 返回顺序重新洗牌。暂时缺失的分组和榜单保留偏好，重新出现时恢复原有选择；有稳定 ID 的分组改名不丢失设置。顶部刷新和浏览后退/前进只改变元数据/位置，不回滚布局偏好，不改变播放或下载。

## 固定元数据协议

使用 `https://u.y.qq.com/cgi-bin/musicu.fcg`，匿名 `uin=0`，不发送账号、Cookie、源 API key 或设备标识，不跟随跳转，不绕过访问限制：

- 榜单目录：`musicToplist.ToplistInfoServer.GetAll`。
- 榜单内容：`musicToplist.ToplistInfoServer.GetDetail`，仅传受限整数 ID、榜期、偏移及每次最多 100 条。
- 新歌目录和内容：`newsong.NewSongServer.get_new_song_info`，地区参数限定当前六种有效 ID。

这些不是承诺开放、稳定的 API。平台限制或结构变化时明确失败，不自动换端点、登录、重试或改用其他平台。

## 完整列表与安全

榜单会按同一榜期和总量分批取得，最多 1000 首、10 次请求，根请求预算 35 秒，每次 HTTP 最多 8 秒、解压后响应最多 2MiB。拒绝错误 ID、榜期变化、总量变化、重复分页或不完整分页，不把部分列表伪称为全部。歌曲信息依 QQ 排名 ID 顺序重排，再使用原有 QQ 歌曲规范化逻辑；数字 songId 保留字符串精度，媒体 MID 和普通音质元数据沿用播放/下载链路。

仅允许目录封面使用 `y.gtimg.cn`，QQ 返回该可信域名的 HTTP 地址时先升级 HTTPS，最终仅返回 HTTPS，拒绝账号、特殊端口及不可信域名，其余图像回退。不采用远端跳转、广告链接、报告字段或原始 HTML；所有文字由 Svelte 转义。

推荐有独立取消通道与代次检查，不取消搜索、歌曲提示、歌词、播放或下载。前端目录最多缓存两种类型、集合最多八项；五分钟内复用，手动刷新始终请求 QQ，相同页面的在途刷新合并。离开页面取消在途请求；返回时可恢复被中断的刷新，迟到的磁盘读取或网络响应不能覆盖新页面。已打开的成功页面不会定时重新联网。

## 缓存优先与后台更新

成功且通过校验的 QQ 目录/完整曲目列表写入当前用户私有 SQLite 的 `state.discovery_cache_v1`，无需 schema 迁移。这里只缓存公开元数据，不保存音乐地址、歌词、源脚本/密钥或失败响应；缓存读取不会访问 QQ、调用音源或开始播放/下载。

- 新打开页面先读取本地成功快照，五分钟内的新鲜内容直接复用；超过五分钟但仍在 72 小时展示窗口内的快照先显示，再后台更新。首次无可用缓存仍需网络，不能凭空消除 QQ 超时。
- 成功刷新替换快照；超时、受限、限流、异常数据或取消不会用失败/空占位覆盖上次成功。上游合法空结果仍是空结果，不等同于请求失败。缓存 I/O 损坏/失败按 miss 或尽力保存处理，不阻断有效的实时元数据。
- 磁盘最多保留两种目录及八条集合；单条 JSON ≤1MiB、总封装 ≤4MiB。按成功保存时间淘汰集合，优先保留目录，避免多看几个榜单就丢掉启动页缓存；这不是永久收藏。读取端拒绝过期、异常未来时间、错榜期、错来源、重复条目和不可信封面地址。保存失败不影响推荐布局草稿等其他 state 键。
- 不增加定时重试、换端点、登录或访问限制绕过，不扩大现有 8 秒 HTTP / 35 秒完整请求预算。这个方案减轻超时对使用的影响，不承诺 QQ 接口本身更快；从未成功读取的列表不能离线伪造。这里只是元数据缓存，不意味着离线音频可播放。

## Wails 与诊断

macOS 推荐缓存/重试的 WebKit 回归已通过；用户已在完整 `.app` 确认断网时未缓存榜单失败、已缓存榜单保留内容的语义正常，并在 `macos-toast-571d503` 完整包确认本轮无重试按钮 toast 改动测试通过。其他未逐项报告的重启和联网恢复场景仍待确认，步骤和本轮证据见 [macOS 验收](macos-testing.md)。不能用浏览器合成桥接替代桌面后端验收。

用户当前反馈：正常联网使用未复现超时；此前诊断样本来自启动后主动断网、打开未缓存榜单并重试，不能据此判定正常联网时的上游故障或调整 HTTP 策略。保留缓存兜底与脱敏阶段诊断，不增加重试或改变限额。


- `GetDiscoveryCatalog(kind, requestID)`
- `GetDiscoveryCollection(kind, id, period, requestID)`
- `CancelDiscovery(requestID)`
- `GetDiscoverySnapshot(kind, id, period)`：`id=0, period=''` 读取目录，否则精确读取对应集合；缺失/损坏/过期返回无数据的快照，不请求网络。

客户端不能提供网络地址。诊断沿用私有有界 `qq-metadata.jsonl`，保留固定操作 `discovery_catalog` / `discovery_collection`、耗时、HTTP 状态和数字业务码；没有榜单/歌曲名称、ID、URL、IP、DNS 主机名、正文、账号、脚本或密钥。

推荐及复用该请求函数的元数据调用额外记录 `timing`：

- `route` 只有 `chart_catalog` / `chart_page` / `new_songs` / `other`；`page` 是 1–10 的请求页次，不是榜单 ID、榜期、歌曲 ID 或请求 ID。
- `stage` 为固定的请求、连接等待、DNS、TCP、TLS、发送、等首字节、响应头、正文、解码、校验或完成枚举。失败阶段可区分一直等首字节和已取得响应头后卡在正文。
- `http_budget_ms` 与剩余的 `context_budget_ms` 用于区分单次 8 秒超时和分页耗尽根请求 35 秒预算；不改变这些限额。`failure` 区分取消、根截止、传输超时、DNS/连接/TLS/正文读取等固定类别，不存原始错误。
- `acquire_ms`、`dns_ms`、`connect_ms`、`tls_ms`、`write_ms`、`first_byte_ms`、`body_ms`、`decode_ms` 为阶段观察值；缺失表示未观察到，不能当作零耗时。超时期间的值包括截至失败的等待，不代表该阶段已完成。`first_byte_observed` 明确是否真正观察到首字节。连接获取包含 DNS/TCP/TLS 等跨度，部分阶段重叠，不能把所有值相加；代理、连接竞争或传输层内部重建也可能影响跨度。它不能单独区分 QQ 处理慢与网络/代理 RTT。
- `reused`、DNS/连接尝试/失败次数、实际读入（可能已解压）的正文字节数都是布尔/数字，不记录代理地址或证书。复用连接不伪造一次新的 DNS/TLS 记录。回调并发安全，结束后冻结；所有字符串字段在落盘前再次按白名单收敛。

日志仍最多 64KiB ×2、按需写入、不上传。Windows 位于 `%APPDATA%\妙音娘子\logs\qq-metadata.jsonl`。从新完整便携包启动后，在实际超时页面点一次刷新，只需提供最近几条推荐的 `operation/result/duration_ms/http_status/timing` 字段，不提供整个日志目录、数据库、脚本或媒体地址。此阶段仅加观测，不自动重试、增大超时或绕过平台策略。
