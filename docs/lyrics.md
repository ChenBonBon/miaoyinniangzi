# 播放详情与逐行歌词

## 交互

点击底栏封面或歌曲名称进入懒加载的播放详情页，展示当前曲目封面、标题、歌手和专辑。返回恢复进入前的主页面；主导航包含推荐、喜欢、下载、设置。歌曲与详情由当前队列索引驱动，下一首同步切换，进出详情不解析或重新播放歌曲。

歌词使用 libmpv 已确认的位置逐行高亮。自动跟随只滚动歌词容器，不滚动整个应用。用户滚轮、触摸、键盘或聚焦浏览时停止跟随，点击「回到当前歌词」恢复。点击时间行调用既有播放器 seek，保持原播放/暂停意图；等待回执期间不拿乐观目标伪装真实进度。启动恢复后若已有有效时长，进度条和时间行可直接选择并保存待播放位置，不解析或自动播放；明确点击播放才将位置应用到新媒体会话。未知时长仍不可定位。无时间轴仅显示原文，不伪造时间。

大窗口封面与歌词分栏，紧凑窗口堆叠；播放器始终保留。歌词使用网格区域内绝对定位的独立视口，避免 WebKit 百分比高度链被内容撑开；仅曲目 ID 改变时复位，播放/暂停及进度刷新不复位滚动。即时跟随使用直接 scrollTop 赋值，不依赖非标准 instant 枚举。行是 shadcn Button，可键盘激活；当前行使用 aria-current。命名滚动区域支持键盘滚动，不使用 application 等错误 ARIA 角色。滚动和颜色过渡遵循 reduced-motion。加载使用 Skeleton，暂无歌词和失败使用 Empty，失败可以显式重试。不展示翻译、逐字歌词或桌面歌词。

## 数据与安全

QQ 匿名元数据接口：`https://c.y.qq.com/lyric/fcgi-bin/fcg_query_lyric_new.fcg`，使用 songmid、format=json、nobase64=1、公开 g_tk=5381。与搜索/建议一样不使用音源脚本或账户 Cookie/API 密钥，不绕过服务限制。请求继承 QQ 客户端超时与不跟随重定向策略，读取最多 512KiB；MID 限制为 ASCII 字母数字且最长 64 字节。

`GetLyrics(songMID, requestID)` 和 `CancelLyrics(requestID)` 有独立取消/版本，不影响搜索、建议、解析或播放。前端切歌和卸载取消请求，迟到结果不能覆盖新歌；仅详情打开时发请求。错误文本固定，不展示原始响应。

后端只处理 lyric 字段，忽略 trans。支持纯 JSON 中普通 LRC 或常见 base64 LRC、HTML 实体、多时间标签、百分/毫秒、全局 offset、稳定排序、相同时刻合并及纯文本回退。正 offset 提前显示。限制最多 4000 输入行/时间行和单行 2000 字符；无效秒数/过大 offset 拒绝。

文字只通过 Svelte 文本插值显示，不使用 HTML 注入。歌词、歌曲 ID 和请求地址不写日志、不写 SQLite或磁盘缓存；前端只保留最多 20 首、10 分钟的内存缓存。默认不记录歌词请求诊断，避免无意落盘原文。

## 验证

- Go：解析、偏移、多标签、同时间分组、纯文本、空响应与错误区分、公开请求头和翻译忽略；Wails 请求取消独立性及迟到清理。
- Node：确认时间二分定位、切歌/销毁拒绝迟到结果、错误重试、空数据与异常响应。
- Playwright：详情入口与返回、启动未播放时的本地位置选择、暂停点行跳转/高亮、曲目切换、100 行歌词在播放/暂停时的手动滚动与前后自动跟随、空/纯文本/失败重试、XSS 文本转义、紧凑窗口与 reduced-motion。Chromium 完整 49 条通过，`MIAOYIN_E2E_BROWSER=webkit npm run test:e2e -- --grep 'restored paused|long lyrics|details'` 的 WebKit 定向回归 9 条通过。
- 系统 WKWebView：启动生产预览到 14873 后运行 `swift frontend/e2e/native-lyrics.swift`，验证恢复选点不自动播放、真实系统滚动布局、播放/暂停状态下滚动不复位、当前行自动居中及恢复跟随。使用合成桥接，不读取用户数据或播放真实音频，已通过。
- `MIAOYIN_LIVE_QQ_LYRICS=1 go test -v ./internal/music -run TestQQLyricsLive` 显式检查真实 QQ 返回的时间轴，不输出歌词正文。已通过。

浏览器测试使用合成原文，仅用于验证交互。最终仍需真实 macOS `.app` 验收歌曲匹配、实际歌词同步和点击行的听感跳转。
